Status: source written without compiling or running anything. No outcome below is a verified result.

## Written

- Signed manifest verification (minisign-verify), discovery with manual HTTPS redirect validation, download with deadlines and a disk-space gate, a durable one-completed-plus-one-replacement cache, a typed state machine, credential ownership, network-cost approval, two-phase install orchestration and startup reconciliation, under `src/update/`.
- Durable installation intent writing added to `src/desktop/profile/installation.rs`.
- Helper binary `chess-update-helper`, native adapters under `src/desktop/native/update/`, and `tools/packaging/verify.rs`.
- Settings update and install views, `docs/update-signing.md`, inert workflow templates, release gate logic in `src/update/release.rs`.
- Deterministic suites in `tests/update/`, `tests/presentation/update.rs`, `tests/desktop/release_workflow.rs`, with a test-only signing fixture generated outside the repository.

## Wiring added afterwards (also unbuilt)

- The update check starts in the background from bootstrap through `DesktopNativeUpdateService`; it is disabled while no public key is embedded or no repository is configured.
- Update commands travel as `DesktopEnumCommand::Update` through the coordinator and return `DesktopEnumValue::Update` snapshots to the Settings view.
- An old installation intent no longer blocks startup once the installed version matches, the helper is not running and storage migrations succeed; the barrier is then cleared.
- Saved engine overrides reach `DesktopNativeGameResources` at its next allocation. Threads and hash are capped by the automatic policy.
